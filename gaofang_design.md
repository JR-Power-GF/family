## Problem Statement

Family stories shared in WeChat groups get buried and lost. The family wants to preserve memories, but the current workflow (sharing in chat) doesn't persist stories in an organized, searchable way. Tech friction makes it hard for some family members to contribute.

## Demand Evidence

- Real pain observed: family members try to share stories but struggle with the interface
- Shared need: the entire family wants to preserve memories
- Current state: stories posted in WeChat groups scroll away and are forgotten

## Status Quo

Stories are shared in WeChat family groups. They appear, get a few reactions, then scroll away as new messages arrive. There's no way to browse old stories, search for specific memories, or see a timeline of family history. Photos and captions are posted separately, making it hard to connect them.

## Target User & Narrowest Wedge

**Target:** The entire family — multi-generational, ranging from tech-savvy to tech-hesitant.

**Wedge:** Photo stories with captions. Not video, not voice, not complex timelines. Start with the simplest unit: one photo + one text story. Anyone can do it.

## Constraints

- Must work as a WeChat mini-program (already set up with uni-app)
- Must be simple enough for older family members to use
- Must persist stories beyond the chat stream
- No external logins — leverage WeChat auth

## Premises

1. **Persistence problem** — Stories get buried in WeChat. A dedicated app solves this. (AGREED)
2. **Simple wedge** — Photos + captions is the right starting point. (AGREED)
3. **Adoption is possible** — Family will use a new app if the value is clear. (AGREED)

## Approaches Considered

### Approach A: Simple Family Feed
A scrollable feed of photo stories. Upload photo, add caption, post. Done.
- **Effort:** S (1-2 days)
- **Risk:** Low
- **Pros:** Ships fast, easy to use, anyone can figure it out
- **Cons:** No organization, grows chaotic over time

### Approach B: Timeline by Date/Event (CHOSEN)
Stories organized by date, grouped by month. Events are implicit from story dates (no explicit event tagging in MVP).
- **Effort:** M (5-7 days for prototype with mock data, 10-14 days for full MVP with backend)
- **Risk:** Medium
- **Pros:** Structured, easier to find old stories, feels like a family archive
- **Cons:** More complex than simple feed

### Approach C: Story Threads by Author
Each family member has their own "story collection" — tap a person to see all their stories.
- **Effort:** M (3-5 days)
- **Risk:** Medium
- **Pros:** Personal connection, encourages contribution
- **Cons:** Less serendipitous discovery, harder to see "what's new"

## Recommended Approach

**Timeline by Date (Approach B)** — Build a timeline view organized by month, with story cards showing photo + caption + author + date.

### Core Features (MVP)

1. **Home Timeline**
   - Stories grouped by month (e.g., "March 2024")
   - Story cards: photo + caption + author name + date
   - Scrollable, chronological

2. **Add Story Flow**
   - Tap "+" button
   - Choose photo from album OR take new photo with camera
   - Write caption
   - Post to timeline
   - Show loading spinner during upload, success toast on completion

3. **Story Detail View**
   - Full photo view
   - Full caption text
   - Author and date

4. **Family Member Attribution**
   - Each story shows who posted it
   - Use WeChat nickname/avatar

### Data Model

```
Story {
  id: string         // Server-generated UUID
  photoUrl: string   // Cloud storage URL
  caption: string
  authorId: string   // WeChat openid
  authorName: string // Denormalized from WeChat profile (simplifies queries)
  authorAvatar: string // Denormalized WeChat avatar URL
  createdAt: timestamp
}
```

**Note:** Author data is denormalized onto each story for read performance. If users change their WeChat nickname/avatar, new stories reflect the change; old stories keep the original value. This is acceptable for a family archive.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Backend storage | WeChat cloud (云开发) | Native integration, no separate server, free tier sufficient for family use |
| Access control | Invite-only via family admin | Prevents strangers from joining; admin shares QR code with family |
| Edit/delete | Authors can edit/delete own stories | Essential for fixing typos and removing accidental posts |
| Pagination | Load 20 stories per fetch, grouped by month; scroll within month loads more | Keeps scroll smooth as archive grows |

## Accessibility Requirements

This app serves multi-generational users, including older family members. Accessibility is a core requirement, not an afterthought.

### Design Decisions (Resolved)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Card tap feedback | Opacity dim (0.7) | Helps older users confirm tap registered; standard WeChat pattern |
| Image zoom in detail | No zoom | Simpler implementation; full photo is already large on screen |
| Author avatar on cards | Yes (avatar + name) | More visual identity; helps recognition across generations |

### Touch Targets

| Element | Minimum Size | Actual Size | Rationale |
|---------|--------------|-------------|-----------|
| Story card (tap area) | 44×44px | Full card | Easy to tap |
| "+" FAB button | 44×44px | 56×56px | Exceeds minimum |
| Primary buttons | 44×44px | 44×44px | Meets minimum |
| Nav icons (back, edit, delete) | 44×44px | 44×44px | Meets minimum |
| Photo source buttons | 44×44px | Full width | Easy selection |

### Color Contrast

All text must meet WCAG AA (4.5:1 for body text, 3:1 for large text):

| Element | Foreground | Background | Ratio | Pass? |
|---------|------------|------------|-------|-------|
| Card caption | #333 | #fff | 12.6:1 | ✅ AAA |
| Card meta | #999 | #fff | 2.8:1 | ⚠️ AA for large only |
| Empty headline | #333 | #fff | 12.6:1 | ✅ AAA |
| Primary button | #fff | #007aff | 4.5:1 | ✅ AA |

**Note:** Card meta (#999) is acceptable because it's supplementary info (author + date), not critical content.

### Text Accessibility

- **Minimum body size:** 14px (28rpx) — readable for older users
- **Line height:** 1.5 minimum for body text
- **No all-caps for long text** — harder to read
- **Caption placeholder:** "Write your story..." (not greyed out until tapped)

### Motion & Animation

- **Skeleton loading:** Subtle pulse (not flashy)
- **Toast:** Fade in/out (200ms each), no aggressive motion
- **Transitions:** Page slides (standard WeChat behavior)
- **Respect reduced motion:** WeChat system setting

### Screen Reader Support

WeChat mini-programs support screen readers via accessibility labels:

| Element | Accessibility Label |
|---------|---------------------|
| Story card | "Story by {author}, {date}. {caption}" |
| "+" FAB | "Add new story" |
| Photo preview | "Photo preview. Tap to change." |
| Post button | "Post story" (disabled: "Post story. Add a photo first.") |
| Edit button | "Edit story" |
| Delete button | "Delete story" |

### Color Blind Considerations

- **Never rely on color alone** for meaning
- Error states: red background + ⚠️ icon + text
- Success states: green checkmark + text
- Offline banner: amber + ⚠️ icon + text

### Cognitive Load

- **One primary action per screen** — Timeline has "+", Add has "Post"
- **No hidden menus** — all actions visible
- **Forgiving** — edit/delete available for mistakes
- **Confirmation for destructive** — delete shows confirm dialog

## Design Differentiation (Avoiding AI Slop)

This is NOT a generic photo feed. Here's what makes it distinct:

### What This Is NOT
- ❌ Instagram-style grid (too visual, loses narrative)
- ❌ Twitter/X-style feed (too text-heavy, buries photos)
- ❌ Chat stream (what we're replacing)
- ❌ "Dashboard with widgets" (wrong mental model)
- ❌ Generic card grid (feels like every SaaS app)

### What This IS
- ✅ **Family photo album, digitized** — evokes physical albums with page-like months
- ✅ **Chronological archive** — time is the primary organization, not algorithm
- ✅ **Story-first, not engagement-first** — no likes, comments, or metrics
- ✅ **Author-visible** — every story shows who shared it (family context)

### Intentional Design Choices

| Choice | Why It's Different | Emotional Goal |
|--------|-------------------|----------------|
| Month headers as section dividers | Not tags, not categories — just time | Feels like flipping through a photo album |
| Author name on every card | Not "posted 2h ago" but "by Mom" | Emphasizes family connection over recency |
| Full-bleed photos on cards | Not thumbnails in a grid | Let the memory breathe |
| No engagement metrics | No likes, hearts, comments | Stories are for preserving, not performing |
| Warm color palette | Not "clean white tech aesthetic" | Feels like home, not an app |

### Card Design Specificity

Story cards are NOT generic content cards. They are:
- **Photo-dominant:** 4:3 aspect ratio photo takes 70% of card height
- **Minimal chrome:** No shadows, no borders, just content
- **Caption as caption:** Styled like a photo caption, not a social post
- **Meta as footer:** Small, grey, right-aligned — like a byline

## User Journey & Emotional Arc

### First-Time User Journey (Happy Path)

| Step | User Does | User Feels | Design Support |
|------|-----------|------------|----------------|
| 1 | Open mini-program | Curious, maybe uncertain | Warm empty state with friendly illustration |
| 2 | See "No stories yet" | Motivated to contribute | Clear CTA: "Add first story" button |
| 3 | Tap "+" or CTA | Ready to create | Large photo area invites action |
| 4 | Choose photo source | Deciding (album vs camera) | Two clear, labeled buttons side by side |
| 5 | Select/take photo | Accomplished, eager | Immediate preview shows success |
| 6 | Write caption | Creative, reflective | Spacious textarea with helpful placeholder |
| 7 | Tap "Post" | Anticipation | Progress bar shows upload status |
| 8 | See "Posted!" toast | Pride, satisfaction | Success toast, auto-navigate to see story |
| 9 | See story in timeline | Belonging, connection | Story card prominently placed at top |

### Time-Horizon Design

**First 5 seconds (Visceral)** — User opens app:
- Clean, uncluttered interface
- Warm colors (not sterile white)
- Clear single action (add story)
- Photo-first design evokes "family album" warmth

**First 5 minutes (Behavioral)** — User browses and posts:
- Obvious affordances: "+" means add, tap card means view
- Consistent card design creates rhythm
- Immediate feedback: loading spinners, toasts
- No dead ends: every state has a path forward

**First 5 years (Reflective)** — User returns to memories:
- Timeline organization makes browsing archives natural
- Old stories remain accessible, not buried
- Denormalized author names preserve "who posted this" even if names change
- Becomes a family heirloom, not just an app

### Key Emotional Moments

1. **Empty State → First Story:** The transition from "nothing here" to "I made this" is the most important emotional beat. The empty state must feel inviting, not sad.

2. **Upload Anticipation:** Waiting for upload is anxiety-inducing. Progress bar and eventual success toast convert anxiety to relief and pride.

3. **Discovery:** Seeing a story posted by another family member creates connection. The timeline should feel like a shared space, not just a personal feed.

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Photo upload fails | Show error toast, retry button, keep caption in memory |
| Network unavailable | Show "offline" banner, queue story for upload when connected |
| Storage quota exceeded | Show alert, suggest deleting old stories |
| Invalid photo format | Filter in picker, only show supported formats (jpg, png) |
